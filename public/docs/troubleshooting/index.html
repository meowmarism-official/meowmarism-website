Troubleshooting

The problems people run into most, and what to do about each.

Pressing Start does nothing

Open the instance's Console. The panel writes why the server did not start. The usual reasons:

  • Wrong Java version. A message like needs Java 25, but Java 21 is installed. Open Manage, then Startup, and press Install Java. New instances get the right Java automatically.
  • Port in use. See below.
  • EULA or files missing. Check the console output.
Tip

If a server crashes right after starting, the crash appears in the console and on the Events page with the last output.

The port is already in use

Another instance or another program uses the Minecraft port. Change server-port on the Settings page, or stop the other program. ss -ltnp | grep 25565 shows what listens on a port.

The update will not start

By default all Minecraft servers must be stopped first, and the message names the running ones. Stop them, or switch the rule off on the panel's Settings page. See Updating meowmarism.

I cannot reach the panel from another computer

  • Check that the port (8090) is open in the firewall.
  • Check that the panel is not set to listen on localhost only (MEOWMARISM_HOST).
  • Check the service: sudo systemctl status meowmarism and journalctl -u meowmarism.

"Too many attempts"

Login protection has locked your IP and username for a short while after several wrong passwords. Wait for the time shown, then try again. It resets after a successful login.

I forgot a member's password

Open Manage users, edit the account and set a new password.

I forgot the owner password

There is no reset button for the owner yet. As the user that runs the service, stop it, replace the owner and start it again. Members and instances are kept:

sudo systemctl stop meowmarism
cd /opt/meowmarism/panel
node -e "const fs=require('fs'),os=require('os'),path=require('path');const f=path.join(os.homedir(),'.meowmarism-controller-users.json');fs.writeFileSync(f,JSON.stringify(JSON.parse(fs.readFileSync(f,'utf8')).filter(u=>u.role!=='owner')),{mode:0o600});console.log(require('./lib/db.js').createUserStore(f).upsertOwner('NEWNAME','NEWPASSWORD'))"
sudo systemctl start meowmarism

It prints true when the new owner was created. Run it as the same user as the service, because the accounts file lives in that user's home directory.

Still stuck?

Look at the console of the instance and journalctl -u meowmarism, then open an issue on GitHub with the message you see.
