Startup, Java and limits

Control how the Minecraft server is launched, and keep it from taking over the machine.

Open an instance, then Manage, then the Startup card. Changes apply the next time the server starts.

Memory and flags

SettingMeaning
Min / max memoryThe JVM heap (-Xms and -Xmx). Leave room for the operating system and other instances.
JVM flagsStandard uses only the memory flags. Aikar's flags is a well-known optimized G1GC set for Minecraft.
Extra JVM argumentsAnything else, each starting with -.
AutostartStart this server when the panel starts.

The values shown come from the server's existing user_jvm_args.txt. Nothing is rewritten until you save a maximum memory value.

Java versions

Minecraft needs a minimum Java version, and it rises over time.

When you create an instance, or upgrade one to a version that needs more, meowmarism checks the host. If the system Java is too old it downloads the right Temurin runtime into ~/meowmarism/java/<version> and sets it for that instance. Before every start the panel checks again and shows a clear message instead of failing silently. For instances created earlier, the Startup card shows Install Java when it is needed.

Linux only

Automatic Java installation supports Linux on x64 and arm64. You can always point an instance to a Java binary of your own in the Startup card.

CPU and RAM limits

Set a CPU limit in cores and a hard RAM limit in MB. How they are enforced depends on the host, and the card tells you which case applies:

  • systemd user cgroups available: real limits for CPU and memory.
  • Only taskset available: the server is pinned to that many CPU cores. RAM is limited by the JVM heap only.
  • Neither: limits cannot be enforced on this host.

Permissions

Memory, flags, limits and autostart need the settings permission. Extra JVM arguments and a custom Java binary need files as well, because they allow running arbitrary code as the panel user.
