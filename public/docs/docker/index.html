Docker and limits

In meowmarism PROFESSIONAL every instance is its own Docker container, with CPU and memory limits that the host enforces.

How it works

The panel creates one container per instance from the image itzg/minecraft-server. The image handles downloading the server, the loader and Java. The panel picks the image tag with the right Java version for the Minecraft version you chose (Java 8, 17, 21 or 25).

Where your data is

The world and all server files stay in a normal folder on the host, ~/meowmarism-pro/instances/<name>, mounted into the container. Files, mods and backups therefore work on plain folders, like in LITE. The files belong to the user that runs the panel, not to root.

Limits

SettingMeaning
Memory (MB)The Java heap of the server. The container limit is this value plus 768 MB for Java itself and the system, and swap is off.
CPUsHow many processor cores the instance may use, in steps of 0.25.
PortThe port players connect to. It is published on the host.

The limits are hard. A server that needs more memory than its limit is stopped by the host and cannot take memory from other instances. The instance page shows current use next to the limit.

Changing a limit recreates the container. A running server is stopped, the container is replaced and the server starts again. The world and settings are kept.

Requirements

  • Docker on the host. The installer offers to install it and adds your user to the docker group.
  • Enough memory for all instances together: each one needs its heap plus 768 MB.

Removing an instance

Deleting an instance removes its container. You choose whether the world and settings are deleted too. Uninstalling the panel keeps your containers and data unless you explicitly choose to delete them.
